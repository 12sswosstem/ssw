## Overview

OX 디자인 시스템에서 숫자(Number)는 금액, 수량, 비율, 상태 값 등 정확성과 신뢰성이 요구되는 핵심 정보 요소로, 정보의 크기와 중요도를 직관적으로 전달하는 역할을 합니다. 숫자의 일관성은 소프트웨어의 가독성, 인지 효율, 신뢰도에 직접적인 영향을 미치며, 타이포그래피 시스템과 동일한 기준 아래 관리되어야 합니다.

- Number는 정보 전달의 **정확성을 최우선**으로 고려합니다.
- **타이포그래피 스케일과 연동**하여 상대적 위계가 유지되도록 설계합니다.
- **동일한 의미의 숫자는 동일한 크기와 규칙**을 사용합니다.
- **임의의 크기 조정 없이**, 정의된 Number 스케일만 사용합니다.

## 기본 기준

- Number는 **Typography 기본 사이즈 체계와 1:1 대응**하여 관리합니다.
- 모든 Number는 **rem 기반 스케일**로 정의되며, 해상도 및 디바이스 환경 변화에 유연하게 대응할 수 있도록 설계합니다.

## Number 스케일 (39단계)

Number 스케일은 숫자 정보의 크기 차이를 일관되게 관리하기 위해 단계적으로 정의된 기준입니다. 각 단계는 px 기준 크기와 rem 단위 변환값을 함께 제공하여, 다양한 해상도와 디바이스 환경에서도 동일한 기준으로 숫자를 사용할 수 있도록 설계되었습니다.

### 변환 공식

```
rem(base=4)  = px / 4
rem(base=16) = px / 16  (웹 표준)
```

### 사용 가이드

- **base=16 rem** = 웹/모바일 페이지의 기본 rem (1rem = 16px). 일반 컴포넌트 사이즈/간격에 사용.
- **base=4 rem** = 4px 그리드 기반 모듈러 스케일. 컴팩트 영역(table cell, inline element 등)에 유용.
- **difference** = 직전 단계와의 px 차이. 시각적 위계 설계 시 참고.

## 의미별 매핑

canonical 39단계 스케일을 기반으로 자주 쓰이는 의미 토큰을 별도로 분리:

| 의미 토큰              | JS 경로                                  | 비고                            |
|------------------------|------------------------------------------|---------------------------------|
| `padding`              | `numberPrimitive.padding`                | 컴포넌트 내부 여백             |
| `gap`                  | `numberPrimitive.gap`                    | auto-layout child 간 간격      |
| `border`               | `numberPrimitive.border`                 | 테두리 굵기                     |
| `height.body`          | `numberPrimitive.height.body`            | body 텍스트 행 높이             |
| `height.button`        | `numberPrimitive.height.button`          | 버튼 라벨 영역 높이             |
| `height.display`       | `numberPrimitive.height.display`         | display 타이포 행 높이          |

각 의미 토큰의 값은 모두 canonical Number 스케일 단계 중 하나여야 합니다.
